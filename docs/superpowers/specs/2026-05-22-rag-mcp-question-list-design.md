# 问题清单整理设计：RAG 与 MCP 专题

## 1. 目标

将截图中的问题整理成一份按知识主题分组的总清单，作为后续专题写作、目录搭建与知识树扩展的输入材料。

本次产物边界如下：

- 输出一篇独立的清单型文档
- 只整理问题，不编写答案
- 保留问题原意，必要时仅做轻量措辞统一
- 按知识主题聚合，而不是按截图原始顺序平铺

## 2. 产物形态

产物是一篇正式 Markdown 文档，包含：

- 标准 Frontmatter
- 文档说明
- 两个一级专题分组
- 每个专题下的二级主题分组
- 每组下的问题列表

不包含：

- 答案正文
- 延伸解释
- 新增截图外问题
- 导航职责与正文职责混写

## 3. 分组结构

### 3.1 RAG 相关

细分为：

- 基础认知
- 知识库构建与系统链路
- Chunking 与切分策略
- 检索增强机制
- 评测与优化

### 3.2 MCP、Tools、Skills 相关

细分为：

- MCP 基础认知
- MCP 核心对象关系
- Tool 设计原则
- Skill 与 Workflow 边界
- 权限、安全与工程约束

## 4. 清洗规则

整理过程中仅允许以下处理：

1. 统一问题表述口径，使标题风格一致。
2. 将高度相关的问题归入同一主题组。
3. 对明显重复的问题做合并，前提是不损失原始含义。
4. 保留原有难度信息中的语义价值，但不强制作为主分组维度。

## 5. 文档放置建议

本次清单优先作为独立问题清单文档存在，而不是直接写入某个 README 或 MOC。

原因：

- 用户当前目标是先形成一份问题总清单
- 清单与导航职责分离后，后续更容易复用
- 后续可从该清单继续拆分专题导航页、单题正文页与写作计划

## 6. 实施结果预期

整理完成后，用户将得到一份可以直接继续演化的专题题库草稿，适用于：

- 后续拆分正式文章
- 构建专题知识树
- 制作教程目录或系列文章路线
- 沉淀为 MOC、README 或写作待办输入

## 7. 实施范围控制

本次只处理截图中可识别的问题，不处理：

- 当前 Docker 笔记内容
- 与截图无关的其他专题
- 现有目录的大规模迁移
- 现有导航文件重构
