# RAG 专题骨架与写作 backlog 设计

## 1. 目标

本次工作只完成 RAG 专题的最小可用启动，不做重复正文建设。

产出目标：

1. 在 `08-AI与智能开发/03-AI应用开发/RAG/` 下建立独立专题入口。
2. 生成 RAG 专题首批写作 backlog。
3. 复用既有 RAG 基础正文，而不是新写一篇平行开篇文。
4. 同步修正父级目录入口与阅读路径说明。

## 2. 已有资产与复用策略

当前仓库已经存在可直接复用的基础正文：

- `08-AI与智能开发/01-AI基础理论/05-RAG 原理.md`

该文已覆盖：

- RAG 是什么
- 为什么需要 RAG
- 核心流程
- 检索与生成主链路
- 常见优化方向

因此本次不再新写 `01-什么是RAG，它主要解决了什么问题.md`，避免形成双入口与内容分叉。

## 3. 目录设计

专题目录放置于：

`08-AI与智能开发/03-AI应用开发/RAG/`

本次只创建当前真实需要承载内容的文件与目录：

- `README.md`
- `99-参考与归档/`
- `99-参考与归档/01-写作选题清单.md`

本次不创建空骨架目录，例如：

- `01-概念与原理/`
- `02-快速上手/`
- `03-核心配置与实战/`
- `04-高阶与调优/`
- `05-常见问题与排错/`

这些目录应在第二批真实正文落地时再按需补建。

## 4. backlog 文档设计

写作 backlog 是专题内部规划资产，不是正式正文文件。

每条选题包含：

- 推荐文章标题
- 知识类型
- 建议目录位置
- 推荐优先级
- 写作目标

文档放置位置：

`08-AI与智能开发/03-AI应用开发/RAG/99-参考与归档/01-写作选题清单.md`

这样可以保证：

- `README.md` 继续只承担目录说明职责
- 正式编号正文只承担知识内容职责
- backlog 不伪装成正文资产

## 5. README 设计

`RAG/README.md` 只承担目录说明与阅读引导职责，不替代正文或 MOC。

内容包括：

- 专题定位
- 当前收录范围
- 目录结构说明
- 与既有基础正文的关系
- 最短阅读路径
- backlog 与正文的角色边界

其中需要显式增加一段“最短阅读路径”，例如：

1. 先看 `05-RAG 原理.md`，建立基础认知。
2. 再看 `99-参考与归档/01-写作选题清单.md`，了解后续扩展方向。

## 6. 父级目录同步更新

必须同步更新：

`08-AI与智能开发/03-AI应用开发/README.md`

原因：

- 该文件当前明确说明本目录聚焦 MCP
- 一旦新增 RAG 专题而不更新，父级入口会立即失真
- 父目录应补充 RAG 专题的当前范围与入口链接

## 7. 验收清单

本次是文档结构变更，因此验收重点是入口、链接与阅读路径，而不是代码行为。

### 7.1 父级入口验收

- 打开 `03-AI应用开发/README.md`
- 确认其中已纳入 RAG 专题说明
- 确认父 README 到 RAG 专题入口链接可打开

### 7.2 子专题入口验收

- 打开 `RAG/README.md`
- 确认 README 只承担目录说明职责
- 确认 README 可跳转到既有 `05-RAG 原理.md`
- 确认 README 可跳转到 backlog 文档

### 7.3 单一入口验收

- 确认未新增第二篇平行“RAG 开篇正文”
- 确认当前唯一基础认知正文入口仍为 `05-RAG 原理.md`

### 7.4 backlog 验收

- 打开 `99-参考与归档/01-写作选题清单.md`
- 确认其文件定位是写作规划资产
- 确认每条选题至少包含标题、类型、建议目录、优先级、写作目标

### 7.5 阅读路径验收

按以下路径完整点击一遍：

`03-AI应用开发/README.md` → `RAG/README.md` → `05-RAG 原理.md` / `99-参考与归档/01-写作选题清单.md`

确认：

- 无断链
- 无错链
- 无重复入口
- 无角色混淆

## 8. 范围控制

本次不做：

- 不新写 `01-什么是RAG，它主要解决了什么问题.md`
- 不迁移 `05-RAG 原理.md` 到新专题目录
- 不创建 `!MOC-RAG.md`
- 不一次性生成前 10 篇正文
- 不重构 `03-AI应用开发` 下其他既有文章
- 不对整个 `08-AI与智能开发/` 目录做全量巡检

## 9. 预期结果

完成后将得到：

- 一个最小但真实可用的 RAG 专题入口
- 一份角色清晰的专题 backlog
- 一个与父目录说明一致的阅读路径
- 一个可继续逐步扩写、但不会从第一天就制造内容分叉的专题起点
