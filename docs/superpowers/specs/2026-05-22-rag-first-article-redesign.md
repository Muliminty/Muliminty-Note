# RAG 首篇正文重写设计

## 1. 目标

将现有 `08-AI与智能开发/01-AI基础理论/05-RAG 原理.md` 重写为 RAG 专题的第 1 篇基础认知正文。

这次重写的核心目标不是补充更多知识点，而是收敛文章职责，使其稳定承担以下角色：

- 解释什么是 RAG
- 解释 RAG 为什么会出现
- 解释 RAG 主要解决了什么问题
- 解释 RAG 不解决什么问题
- 为后续专题文章建立阅读起点与拆分空间

## 2. 范围控制

本次只改正文内容定位，不改结构归属。

明确不做：

- 不修改文件路径
- 不迁移到 `RAG/` 专题目录
- 不重命名文件
- 不新增平行开篇文
- 不同时拆分出 Chunking、Recall、Rerank、评测等后续子文
- 不对同目录其他 AI 基础理论文章做联动重构

## 3. 现状问题

当前 `RAG 原理.md` 的信息量较大，覆盖了：

- 定义
- 问题背景
- 完整流程
- 离线 / 在线阶段
- Chunking
- Embedding
- Retrieval
- Generation
- 评估指标
- 常见优化方向
- 进阶架构

这些内容本身没有错误，但对“专题第 1 篇”来说过于厚重，导致文章角色偏向“总览型知识压缩包”，而不是“帮助读者先建立正确认知入口的开篇文”。

## 4. 新正文职责

重写后的正文应聚焦 4 个核心问题：

1. RAG 是什么
2. RAG 为什么会出现
3. RAG 主要解决了什么问题
4. RAG 不解决什么问题

只要这四个问题讲清楚，这篇文章就达到了专题开篇的目标。

## 5. 新结构设计

建议采用如下结构：

### 5.1 是什么

- 给出一句话定义
- 解释“检索增强生成”增强的是什么
- 明确它不是训练方法，而是推理阶段引入外部知识的系统架构

### 5.2 为什么会出现

围绕 LLM 单独使用时的局限展开：

- 知识截止
- 私有知识不可见
- 事实性幻觉
- 纯靠模型参数记忆不够

### 5.3 它主要解决了什么问题

重点说明：

- 如何接入私有知识
- 如何补充最新知识
- 如何提升回答可追溯性
- 如何降低部分事实性幻觉风险
- 如何降低“为了补知识而微调”的成本

### 5.4 它是怎么工作的

只保留最小工作流程：

- 用户提问
- 检索相关内容
- 拼接上下文
- 模型生成回答

允许保留一个最小链路图，但不在本篇里深入展开工程实现细节。

### 5.5 它不解决什么问题

明确列出边界：

- 不会自动消灭幻觉
- 不保证检索一定正确
- 不等于微调
- 不等于 Agent
- 不等于“接个向量数据库就一定好用”

### 5.6 什么场景适合用 RAG

给出工程上常见的高匹配场景：

- 企业知识库问答
- 文档问答
- FAQ 系统
- 需要引用来源的问答系统
- 时效信息密集的业务场景

### 5.7 关联知识

为后续文章预埋阅读路径，例如：

- Embedding 与向量表示
- Chunking
- Recall / Rerank
- Query Rewrite
- RAG 评测指标

## 6. 内容删减与下沉原则

现有文章中的以下内容不应在第 1 篇里展开过深：

- 过长的离线 / 在线流程拆解
- 过多工具枚举
- 过深的检索优化策略罗列
- 过多评测指标细节
- 进阶架构的大段展开

处理方式不是删除，而是：

- 保留最低限度说明
- 用一句话点到为止
- 把深度展开留给后续单篇文章

## 7. 写作风格要求

重写后的口径应满足：

- 先讲问题，再讲定义
- 先给心智模型，再讲技术结构
- 用工程语境解释技术意义，而不是百科式堆料
- 兼顾基础认知与后续展开的承接关系

目标读者是有工程背景的开发者，因此文章不需要停留在概念口号层，而要解释“为什么这个架构值得存在”。

## 8. 与专题结构的关系

重写完成后，该文将同时承担两层角色：

- 作为 `01-AI基础理论` 中的一篇正式基础文章存在
- 作为 `03-AI应用开发/RAG/README.md` 当前引用的唯一基础认知正文入口

这可以保持：

- 不制造双入口
- 保持单一知识源
- 让专题入口与正文入口分工清晰但互相衔接

## 9. 验收标准

### 9.1 内容验收

- 能独立回答“什么是 RAG”
- 能独立回答“RAG 主要解决了什么问题”
- 能让读者理解“为什么会有 RAG”
- 能明确知道“RAG 不是什么”

### 9.2 结构验收

- 开篇比现状更聚焦
- 不再试图在一篇里塞满全部后续知识点
- 后续子主题具备自然拆分空间

### 9.3 专题验收

- 可自然被 `RAG/README.md` 作为第一跳引用
- 不需要新增第二篇重复正文
- 不破坏现有 AI 基础理论目录的阅读连续性
