# RAG 问题排错

本子目录承接 RAG 专题的实战踩坑沉淀，聚焦"系统看起来跑得动，但效果不对"的真实问题。所有文章均以**问题复现 → 归因分析 → 修复方案**的链路展开。

## 1. 子目录定位

本目录不承担算法原理讲解，也不重复 [03-核心配置与实战](../03-核心配置与实战/) 的选型对比。它专门收纳那些**只有动手做过才会遇到**的问题，例如：

- 召回结果看起来相关，但回答总是答非所问
- 命中率上不去，分不清是切分、Embedding 还是 Query 的责任
- 大文档检索后，关键信息在拼接阶段被截断
- 评测分数每次波动很大、不可复现

## 2. 写作要求

每篇排错笔记必须遵循 [问题排错类模板](../../../../99-系统/模板/03-问题排错类模板.md)，至少包含：

- 现象与最小复现条件
- 关键日志、检索结果或评测指标截取
- 归因分析（含被排除的可疑项）
- 修复方案与验证方式
- 复盘与可复用经验

不允许只写"我碰到这个问题，加了个参数就好了"这类无归因笔记。

## 3. 已落地文章

本目录正在筹备中，暂无正式文章落地。等待真实项目踩坑后按需补写。

## 4. 待落地内容（来自第二批选题清单）

- 召回对但回答跑偏
- 命中率低的归因分析
- 大文档上下文丢失
- 评测分数不稳定

完整清单与写作目标见 [写作选题清单](../99-参考与归档/01-写作选题清单.md) 第二批 F 组。

## 5. 维护约束

- 排错文必须基于真实场景沉淀，不接受纯推测性内容
- 涉及敏感数据时，应做脱敏处理后再贴日志或检索结果
