# RAG 与 MCP、Tools、Skills 问题清单

> 这是一份按知识主题分组的专题问题清单，用于后续继续拆分文章、构建知识树与规划写作顺序。

## 1. RAG 相关

### 1.1 基础认知
- 什么是 RAG？它主要解决了什么问题？
- 为什么引入了 RAG 之后，模型幻觉并不会自动消失？

### 1.2 知识库构建与系统链路
- 创建知识库的流程是什么？使用 RAG 做切分与检索的主要思路是什么？
- RAG 的完整链路一般包括哪些步骤？如何理解用户输入、检索、向量数据库与大模型之间的配合关系？
- 如果用户提问非常模糊，RAG 系统应该如何处理？
- 你会如何设计一个支持 PDF、网页、文档等多来源数据的 RAG 知识库？
- 什么是 Metadata？为什么 RAG 系统通常需要 Metadata？
- 知识库内容存在时效性时，RAG 系统应该如何处理更新、失效与版本问题？
- 如果知识库里存在互相冲突的信息，RAG 系统应该如何处理？

### 1.3 Chunking 与切分策略
- 分块的策略是什么？如何进行分块？
- 为什么“分块（Chunking）策略”会直接影响检索质量？
- 固定长度分块和按语义分块，各有什么优缺点？
- Chunk 太大和 Chunk 太小分别会带来什么问题？
- 什么是 Overlap？为什么要做 Overlap？Overlap 应该怎么设计？

### 1.4 检索增强机制
- 什么是召回（Recall）？什么是重排（Rerank）？
- 什么是 Query Rewrite？为什么很多 RAG 系统需要 Query Rewrite？
- 什么是引用源（Citation）？为什么 RAG 回答里需要显式引用来源？
- 如何设计一个“答不上来就明确答不上来”的 RAG 系统？
- 如何判断 RAG 问题到底出在切分、召回、重排、Prompt，还是生成阶段？

### 1.5 评测与优化
- RAG 系统常见的评测指标有哪些？
- 如何系统评估一个 RAG 系统的检索质量、回答质量与可用性？
- 当 RAG 效果不好时，应该按什么顺序排查与优化？

## 2. MCP、Tools、Skills 相关

### 2.1 MCP 基础认知
- MCP 的核心价值是什么？它试图解决什么问题？
- 普通后端接口和 MCP Tool 的区别是什么？
- MCP 在工程落地中的最大挑战是什么？

### 2.2 MCP 核心对象关系
- MCP Server、Tool、Resource、Prompt 之间是什么关系？
- 什么是 Resource？它适合承载什么类型的信息？
- Prompt 在 MCP 体系里更适合扮演什么角色？

### 2.3 Tool 设计原则
- 为什么说 Tool 本质上是“给模型开放能力边界”的接口？
- 如何设计一个适合被模型调用的 Tool？
- 普通接口设计与面向模型调用的 Tool 设计，有哪些本质差异？
- 一个 Tool 需要具备哪些特征，才更适合被 Agent 稳定调用？

### 2.4 Skill 与 Workflow 边界
- 什么是 Skill？它和单个 Tool 的差别是什么？
- Skills 和 Workflow 的区别在哪里？什么时候应该使用 Skill？什么时候应该使用 Workflow？
- 为什么在复杂业务里，单纯堆 Tool 往往不如设计 Skill 或 Workflow？
- 在什么情况下，应该把多个 Tool 抽象成一个 Skill 或一个 Workflow？

### 2.5 权限、安全与工程约束
- 为什么接了 Tool 的 Agent 系统，安全风险会明显增大？
- 如果 Tool 能访问数据库或执行命令，权限边界应该怎么设计？
- MCP 场景下，如何做权限隔离和能力收敛？
- 如果一个 Tool 非常危险，比如可以删库、执行命令或操作文件，应该如何设计调用保护机制？
- 如何控制模型在使用 Tool 时的误调用、越权调用与链式放大风险？
