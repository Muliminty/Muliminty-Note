# 多行文本省略号下方露字复盘

## 1. 现象

卡片标题期望最多显示两行，并在第二行末尾显示省略号，但实际效果是：

- 第二行已经出现省略号；
- 省略号下方仍露出第三行文字的一部分；
- 不同浏览器或 WebView 中露出的高度可能不一致。

典型文本示例：

```text
物理AI先看马斯克链？
智能驾驶、机器人、...
航空航天...
```

## 2. 原始写法

```css
.title {
  display: -webkit-box;
  overflow: hidden;
  min-height: 1.3125rem;
  padding: 0.25rem 0.28125rem 0.3125rem;
  font-size: 0.875rem;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 2;
  text-overflow: ellipsis;
}
```

## 3. 根因

### 3.1 `line-clamp` 与 padding 的兼容边界

`-webkit-line-clamp` 是基于 WebKit 多行布局实现的截断能力。部分浏览器内核在截断元素同时设置上下 `padding` 时，会将 padding 参与可视区域计算，导致截断边界下方露出下一行的字形。

因此，`overflow: hidden` 并不一定能阻止这类“半行露字”，因为露出的内容仍处在该元素计算出的可视区域内。

### 3.2 未显式设置 `line-height`

`line-height: normal` 由浏览器和字体决定，实际行高可能是小数像素。两行行高、上下 padding 和最小高度叠加后，容易出现边界取整差异，在移动端 WebView 上尤其明显。

### 3.3 `text-overflow` 不是多行截断的核心属性

`text-overflow: ellipsis` 主要用于单行文本。多行省略号主要由 `-webkit-line-clamp` 生成，单独设置 `text-overflow` 不能修复多行露字。

## 4. 稳妥修复

把布局内边距和文本截断拆到两个元素：外层负责 padding，内层负责 line-clamp。

```jsx
<span className={styles.title}>
  <span className={styles.titleText}>{video.title}</span>
</span>
```

```css
.title {
  display: block;
  min-height: 1.3125rem;
  padding: 0.25rem 0.28125rem 0.3125rem;
  color: #333;
  font-size: 0.875rem;
  line-height: 1.3125rem;
}

.titleText {
  display: -webkit-box;
  overflow: hidden;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 2;
}
```

关键原则：不要让带 padding 的元素同时承担多行截断职责；同时显式设置行高，让两行文本的高度可预测。

## 5. 可运行复现 Demo

将下面内容保存为 `line-clamp-demo.html` 后直接用浏览器打开。左侧是容易出现底部露字的写法，右侧是拆分容器后的写法。

```html
<!doctype html>
<meta charset="utf-8" />
<title>line-clamp 露字复现</title>
<style>
  body {
    display: flex;
    gap: 16px;
    padding: 16px;
    font: 14px/1.5 sans-serif;
  }

  .card {
    width: 180px;
    border: 1px solid #ddd;
    background: #fff;
  }

  .label {
    padding: 6px;
    color: #666;
    font-size: 12px;
  }

  /* 问题写法：截断元素自身带上下 padding。部分 WebKit 内核会露出半行。 */
  .bad {
    display: -webkit-box;
    overflow: hidden;
    padding: 4px 6px 5px;
    font-size: 14px;
    -webkit-box-orient: vertical;
    -webkit-line-clamp: 2;
    text-overflow: ellipsis;
  }

  /* 修复写法：外层负责间距，内层负责截断，并固定行高。 */
  .good {
    padding: 4px 6px 5px;
    font-size: 14px;
    line-height: 21px;
  }

  .good > span {
    display: -webkit-box;
    overflow: hidden;
    -webkit-box-orient: vertical;
    -webkit-line-clamp: 2;
  }
</style>

<div class="card">
  <div class="label">问题写法</div>
  <div class="bad">物理AI先看马斯克链？智能驾驶、机器人、航空航天谁先落地？</div>
</div>

<div class="card">
  <div class="label">修复写法</div>
  <div class="good">
    <span>物理AI先看马斯克链？智能驾驶、机器人、航空航天谁先落地？</span>
  </div>
</div>
```

预期结果：在受影响的 WebKit/WebView 环境中，左侧可能在省略号下方露出第三行字形；右侧始终只显示两行。若桌面浏览器无法复现，也应在目标 Android/iOS WebView 中验证，因为该问题与内核实现和字体行高有关。

## 6. 排查清单

遇到“省略号下面还有字”时，按以下顺序检查：

1. 元素是否同时具备 `display: -webkit-box`、`-webkit-box-orient: vertical`、`-webkit-line-clamp` 和 `overflow: hidden`。
2. 截断元素是否设置了上下 `padding` 或 `border`。
3. 是否缺少明确的 `line-height`。
4. 是否误以为 `text-overflow: ellipsis` 可以独立处理多行文本。
5. 是否存在全局 `box-sizing`、缩放根字号或移动端 WebView 导致的尺寸取整差异。
6. 标题是否包含换行符、内联元素或其他会改变行盒计算的子节点。

## 7. 验证方式

- 使用超出两行的中文、英文、数字和混合文本分别验证。
- 在 Chrome/Edge 和实际 Android/iOS WebView 中检查底部是否仍露字。
- 检查短标题是否保留原有 padding，长标题是否严格最多两行。
- 用开发者工具查看标题元素的实际高度，确认高度约等于 `两行 line-height + 上下 padding`。

## 8. 经验结论

多行文本截断属于浏览器布局能力，不应只依赖一组属性“碰巧生效”。稳定实现的优先级是：

1. 分离布局容器和截断容器；
2. 显式设置 `line-height`；
3. 让高度由行高和 padding 明确推导；
4. 用目标浏览器和真实 WebView 做回归验证。
